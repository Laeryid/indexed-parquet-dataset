# indexed-parquet-dataset: Публикация новой версии

## Overview

Скилл выполняет цикл релиза пакета `indexed-parquet-dataset`. 
Так как проект использует `setuptools-scm` (указано в `pyproject.toml`), версия пакета определяется исключительно **git-тегами**. Изменять хардкодом версию в коде не нужно — файл `_version.py` генерируется автоматически.

## Trigger phrases

Запускается при запросах (или схожих по смыслу):
- «создай релиз»
- «опубликуй новую версию»
- «запушь версию»
- «выпусти релиз»

## Workflow

### Шаг 1: Определение текущей версии и согласование следующей

1. Выполни `git tag --sort=-v:refname` для получения списка последних тегов.
2. Проанализируй изменения с момента прошлого релиза.
3. Предложи пользователю следующую версию (patch, minor или major согласно SemVer) и спроси подтверждения:
   > «Текущая версия — `vX.Y.Z`. Предлагаю выпустить `vX.Y.W`. Подтверждаешь или хочешь указать другую версию?»

> [!IMPORTANT]
> Не выполняй никаких изменений без явного согласия пользователя.

### Шаг 2: Обновление CHANGELOG.md

После согласования версии:
1. Открой файл `CHANGELOG.md` в корне проекта.
2. Аккуратно замени заголовок `## [Unreleased]` на два заголовка: пустой `## [Unreleased]` (для будущих правок) и заголовок новой версии `## [X.Y.Z] - YYYY-MM-DD` (текущая дата). 
   Пример замены:
   ```markdown
   ## [Unreleased]
   
   ## [X.Y.Z] - YYYY-MM-DD
   ```
   В результате все изменения, которые были под `[Unreleased]`, окажутся под заголовком новой версии.
3. Сохрани файл.

### Шаг 3: Коммит, тегирование и пуш

Запроси у пользователя подтверждение на коммит и пуш изменений. Если он согласен, выполни:

```powershell
git add CHANGELOG.md
git commit -m "chore: release vX.Y.Z"
git tag vX.Y.Z
git push origin main
git push origin vX.Y.Z
```

### Шаг 4: Подтверждение успеха

Сообщи пользователю:
- Изменения зафиксированы, тег `vX.Y.Z` успешно отправлен на GitHub.
- Напомни, что благодаря `setuptools-scm`, версия была автоматически зафиксирована из тега, а GitHub Actions (если они настроены) автоматически соберут пакет и отправят его на PyPI.

## Common Mistakes

1. **Забыли букву `v` в теге**: убедись, что тег начинается с буквы `v` (например, `v0.4.1`), так как проект исторически использует этот формат.
2. **Попытка ручного изменения `_version.py`**: никогда не редактируй этот файл вручную, он должен игнорироваться или обновляться автоматически при сборке.
